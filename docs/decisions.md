# 关键决策（为什么这么设计）

> 只记**现行有效**的决策与理由；被推翻的结论不再保留。

## 五条设计原则

| # | 原则 | 落地 |
|---|------|------|
| ① | **理解要柔性，状态要硬** | 平台不抽参数（用户原话原样传）；状态由代码写、分支穷举 |
| ② | **能靠既有事实判定的，不发明协议** | 删掉了 `finish` / `status` 枚举 / `deliverables` / `criteria` |
| ③ | **能靠代码算的，不交给 LLM；能靠 schema 约束的，不靠提示词** | 决策走 `with_structured_output`；三态干脆不是 LLM 决策（由结构定） |
| ④ | **平台少约束 skill 作者** | 形式能跑即可，效果由作者迭代——任何**依赖作者配合**的机制都是脆的 |
| ⑤ | **交接靠硬机制，软判断收紧到最紧** | 委托负载平台**硬拼**；要信息由执行器**自己申报**；平台发起的 LLM 调用只剩试答一处 |

## 砍掉的（曾经以为必需）

| 砍掉 | 为什么 |
|---|---|
| `finish` 工具 | **产物落盘就是完成**——用工具参数传决策，模型不调，决策就丢了 |
| `status` 枚举 / `deliverables` 清单 / `criteria` | 平台约定只有一句"交付物调 `write_artifact`"；"产物在不在"这个既有事实就够了 |
| 判定那次 LLM 调用 | "完成没"归主 agent、"在不在要信息"归执行器申报——两个语义拆开，**根因移除**（不是"判不准"） |
| `interrupt` 模式 | 它要解决的问题已用别的方式解决（见下） |
| 草稿 / 断点外置 | **接受重跑**——换掉一整类 bug |
| 参数声明（`Skill.params`） | 逼作者声明 = 约束作者；且实测模型会改写参数名、算错并集——**硬路径换不来可靠性** |

## 几条最贵的教训（全是实测换来的）

**① 模型的话是线索，不是事实。** 同一个坑踩了三次：声称完成 → 误判成交付；
自报交付清单 → 拿去精确匹配 → 误判缺失；提示词约束参数名 → 模型改写。
**推论**：模型的产出要参与逻辑判断的地方，**要么用代码验证它，要么别用它**。

**② 平台只保证产物。** 正文交付不保证、也不为它造机制——
四家参考实现没有一家支持"交付物在正文里"（交付物一律走独立通道）。

**③ 别断言模型走了几步。** LLM 是概率的，数量断言必然脆；
有效性靠**平台造路**（校验 / 枚举 / 拒绝 / 按需取），不靠措辞。

**④ 不要用正则处理语义。** 语义是**开放集合**，枚举不到的写法不会报错、只会**静默漏过**。
判据分两类：机械的（键集合 / AST / 文件在不在）→ 进守卫（**会红**）；
语义的（"说清了吗"）→ **别造守卫**，如实说没有机制，靠周期性 LLM 审。**假红比不守更坏。**

## 为什么不走 `interrupt()`（最容易被误读的一条）

**不是 interrupt 不好**——实测它跑得通，主上下文还更小。
是**它要解决的问题这里已经用别的方式解决了**：

- "提问走向不确定" → **执行器从不直接问用户**（没有"答给谁"的歧义）
- "挂起恢复" → `Task.stage` 由**代码**写，恢复是**纯代码查表**，LLM 不参与

若将来确实要做 HITL：把提问做成**图节点**而不是工具——
节点里调 `interrupt()` 不产生 `tool_call`，"悬空 ToolMessage → 上游 400"从根上消失。

## 设计依据（不是独创）

| 来源 | 借鉴了什么 |
|---|---|
| **DeepAgents** | subagent 的 `task` 工具 · skills 渐进式加载 · 子 agent ephemeral/stateless |
| **Claude Code Skills** | `SKILL.md` 渐进式披露 · **subagent 上下文隔离（子 agent 不能反问用户）** |

**决定性发现**：参考实现的子 agent 是"**纯函数**"（一次报告、无状态）——
"重复问用户 / 状态间歇丢失 / 提问写进正文"在它那里压根不会发生。
本库的**新颖部分很少**：主要是把业界已验证的结构搬到"**需要跨轮交互**"的场景上，
并补上 `Task` 这一层状态载体。

## 工作方式（做设计时怎么配合 —— 同样适用于下一次迭代）

批判性审视（先看业界怎么做再决定自造）· 讨论先行（说清"验什么/怎么验/预期"再写代码）·
**结论必须实测**（"想当然"几乎全被推翻）· 分支必须闭合（靠约定排除的组合 = 该用枚举）·
保留历史不删（过期结论标"已被取代"+ 一句为什么，**未标记的过期内容比没有更糟**）。
